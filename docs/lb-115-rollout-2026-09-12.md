# Dedicated LB rollout state — 2026-09-13

## Current state

The dedicated controller and embedded UI are live at
`https://10.0.0.115:8443` (Admin `/admin/`, Studio `/studio/`, Chat `/chat/`).
This is the separate LB, not the WSL test instance. PostgreSQL, the Garage
object store, its localhost-only HTTPS nginx proxy, and the controller are
enabled and active under systemd. The old Node `lb-proxy.service` remains
active on port 4000; it was not restarted or cut over. The LB root filesystem
is now 20 GB with about 17 GB free after installation.

Production config is `/etc/vram-governor/controller.yaml`, with private service
environment `/etc/vram-governor/controller.env`. Fresh, distinct raw plane and
node tokens plus the shared node-command signing secret are root-only in
`/root/vram-governor-controller-credentials.env` on the LB. Do not copy that
file into the repository or paste it into logs. The public self-signed
controller certificate is `/etc/vram-governor/tls/controller.crt`; clients
must trust it explicitly before using HTTPS/WSS without a warning. Its IP SAN
is `10.0.0.115`.

The S3-compatible Garage service is version 2.4.1. It stores data under
`/var/lib/garage` on the LB root volume, listens on `127.0.0.1:3900`, and is
exposed to the controller only through verified HTTPS at
`https://127.0.0.1:9443`. This is single-node, single-volume storage:
persistent across restarts, but without a replica or off-host backup. Upgrade
that durability before relying on irreplaceable video artifacts.

The managed CMP170 video target and OpenRouter fallback are disabled until
their actual runtimes/credentials are supplied. The CMP170 smart plug at
`10.0.0.222` is configured read-only (`control_enabled: false`). An
authenticated live API check reported it reachable; no relay command was
sent. `.43` and `.82` are not mapped.

Live verification from the LB passed HTTPS health, all three UI paths,
unauthenticated/wrong-plane admin denial, authenticated Admin overview,
CMP170 plug telemetry, and an authenticated artifact upload/download through
Garage. The same checks passed again after restarting only the new Garage,
nginx, and controller services. A separate Windows-side check validated the certificate and got HTTP
200 from Admin. The live overview showed **zero connected node agents**. The
earlier endpoint script in `.cache/hardware-test/` points at the WSL test
controller `10.0.0.186:18082`, not this LB, and uses a different
certificate/token. Worker enrollment is outside this LB-only rollout; do not
claim the three GPU boxes are already linked. The verified 1.2.1 Linux agent
archive and pinned-certificate rebind helper are staged under `/root` on the
LB; see [the node connection guide](connect-gpu-nodes-to-lb.md).

For a repeatable LB check, run `bash /root/verify-lb-115-live.sh` as root on
the LB. It makes one tiny `/etc/hostname` artifact upload. Service recovery:
`systemctl status vram-garage nginx postgresql vram-governor-controller`;
`journalctl -u vram-governor-controller -u vram-garage -u nginx -n 100`.
Configuration is guarded by
`/usr/local/libexec/vram-governor/validate-controller.sh` before every
controller start. The one-time provisioning source is
`scripts/provision-lb-115.sh`; rerunning it after configuration exists refuses
to rotate credentials.

The old proxy has not been replaced or restarted. No smart-plug relay command
was sent during this rollout. Database rollback, if ever required, needs a
snapshot/restore rather than rerunning migrations in reverse.

`vram-governor-controller.service` is inactive; `lb-proxy.service` and

No NFS/CIFS mount or S3 service was found on the LB, and its root filesystem

SSH to those two addresses also timed out. The template worker names do not

intended GPU hosts, and do not place an unbounded video artifact store on the
7.8 GB controller root disk.
