## Available implementations

| Selector | Operation | Models | Output |
|---|---|---|---|
| `image-sdxl-base@1` | `image.generate` | SDXL base 1.0 | PNG + JSON manifest |
| `video-wan22-5b@1` | `video.generate_sequence` | Wan 2.2 TI2V 5B, FP8 UMT5 encoder, Wan 2.2 VAE | MP4 + JSON manifest |

Use `https://10.0.0.115:8443` with certificate verification enabled. Authenticate with a workflow credential for Creator API requests, or the Comfy MCP credential for the Comfy-compatible gateway. Existing credentials remain in the LB's protected `/root/vram-governor-controller-credentials.env`; do not put their values in source, documentation or command arguments. The LB trust certificate is `/etc/vram-governor/tls/controller.crt` on `.115`.

- Discover implementations: `GET /api/v1/capabilities`.
- Submit Creator work: `POST /api/v1/workloads` with explicit `profile_preferences.preferred`, `fallback_policy: "explicit"`, and a compiled graph inside `payload.managed_chunks[0].prompt`.
- Poll: `GET /api/v1/workloads/{workload_id}`.
- Fetch an output: strip `artifact://` from its `artifact_ref`, then `GET /api/v1/artifacts/{id}/content` using the same credential.
- Comfy-compatible transport: `POST /prompt`, followed by `/history/{prompt_id}` and `/view`. Its managed transport accepts `managed_chunks`; see the package examples.

Full request examples are in [the bootstrap instructions](../configs/comfy-bootstrap/README.md). Workflows are API-format Comfy graphs, not natural-language request strings. The client supplies/compiles the graph; the profile registration does not implement a semantic prompt-to-workflow translator. This deployment proves API access, not a Comfy canvas/editor mounted at the LB address. Standard Comfy `/object_info` and `/system_stats` are not currently exposed by the LB gateway; a client requiring those endpoints needs separate discovery support.

Source review also confirms that the managed harness accepts a standard `{"prompt": <graph>}` as one chunk when the scheduler selects that target; `managed_chunks` is not the only accepted format. This native-format path has not yet received a live MCP acceptance test. Managed history currently retains a backend-prompt-id map inside the public prompt-id response, which can prevent a standard client from finding `outputs` at the expected level. Normalizing single-graph history and adding authenticated, bounded discovery remain required before claiming drop-in Comfy MCP compatibility. The tested Creator API examples above are unaffected.

The node's large Comfy 0.34.0 catalog exceeded the controller's default 32 KiB WebSocket read limit. It disconnected immediately after registration, leaving GPU inventory empty and scheduling blocked. The raw Comfy target was already disabled; its redundant discovery endpoint in `/etc/vram-governor/node-agent.yaml` is now blank. The managed harness route is unchanged. Fresh signed telemetry now reports `cmp170-node-gpu0`, NVIDIA RTX 3080, 10240 MiB, and the node remains connected.

This is a configuration workaround, not the permanent transport fix. It also disables the node agent's raw Comfy reclaim path and skips Comfy reclaim during its `drain_runtimes`; the separate managed harness remains usable. Do not re-enable raw discovery before deploying a reviewed bounded WebSocket message-limit fix. No checkpoint, multiple-resident-model or automatic-displacement capability was enabled by this setup.

During registration, an initial root-authored update failed because replacement lost the config's service group. Prior config contents and service ownership were restored and verified healthy. The corrected helper preserves uid/gid/mode, checks service-user read access before replace, and then waits for verified TLS health. Final config retained every unrelated value. Only its managed target's `models`, `custom_nodes`, and `profiles` changed. The node config changed only the redundant Comfy endpoint. Comfy, harness, video-worker, llama-server, and runtime-tunnel services were not restarted.

The rig is intentionally left powered on for the requested Comfy testing. No `.222` toggle was performed. The earlier clean-shutdown/outlet-off policy still applies once it is no longer needed.
