## Local bounds and filesystem policy

Current root rule: after authentication, the archive may use `package`, the safe basename or basename-plus-major/minor form derived from an authenticated `@types/<basename>` identity, or an ordinary unscoped safe package basename under ASCII case folding followed by literal `-v` and the exact canonical numeric `x.y.z` version from that same identity. Only the ordinary basename portion is case-folded. Every member keeps one exact literal spelling across its raw path, header path, effective PAX path, and root annotation; mixed roots and case aliases fail. All validated roots map to canonical `package/...` outputs while original root provenance remains recorded. The detailed historical schema/root references below are superseded by the Repair27 current-status and mode criteria above.

Inspection license/notice evidence includes the archive member index as well as canonical path, byte count, digest, and decoded text, so identical-content path aliases remain individually attributable; the report assembler reconciles that evidence against every matching member in the complete archive inventory.

The helper caps local reads before allocation: lock 1,000,000 bytes; plan 8 MiB; acquisition manifest 128 MiB; pnpm evidence 4 KiB; metadata 1 MiB; archives 64 MiB by default and 128 MiB only for the exact locked Iconify exception; package manifest 2 MiB. The Iconify cap is enforced on the network stream, persisted archive reads, manifest record, and extraction recheck from the full authenticated lock record paired to the checked ordinal; it cannot be supplied or raised by a caller. Aggregate compressed archives remain 3 GiB. Expanded archive bounds are 512 MiB each and 8 GiB aggregate. Each archive is limited to one million members; globally, archive-member count plus every created output-directory count (including `unpacked/`, ordinal roots, explicit directories and synthesized parents) is at most one million. Actual output-tree walk is independently capped at one million paths. The emitted extracted inventory is capped at 256 MiB and that serialized-size reservation is checked before output creation. Inspection separately caps each license/notice payload at 8 MiB, all such payloads at 128 MiB, and its complete report at 256 MiB before create-new write. Streamed file reads detect growth and compare opened/current identities, link count, size and path state.

Every `lstat` and file-handle `stat` requests BigInt fields. `dev`, `ino`, and `mode` stay BigInt for exact opened/path/parent comparisons and serialize as canonical bounded decimal strings (`dev`/`ino` uint64, `mode` uint32); `size` and `nlink` are independently bounded before exact safe conversion or comparison. The final inventory reserves each identity at maximum decimal width before any extraction effect. Pure fixtures cover adjacent inode values above 2^53, exact JSON round-trip, malformed/unsafe values, changed opened/parent identities, and reservation coverage. Every read/write target is workspace-contained. Existing path ancestors are checked for symlink/reparse attributes; workspace root is checked against `realpath`; parent/created identities are rechecked around each create-new effect. Mapping names use deterministic ordinal components and are checked for collision, case, normalization, device-name, ADS, reserved-character and path-length hazards before network or writes. Archive paths retain strict-UTF8 framing and accept only ASCII, Windows-safe non-dot components after one authenticated archive root. Only exact `.` components after that root are removed lexically; `..`, empty segments, leading-dot roots, absolute/drive/backslash paths remain forbidden. Raw path length is capped at 4,096 bytes, each non-dot component at 255 bytes, and computed canonical full extraction paths at 240 characters. Original header name/prefix/path, effective PAX path and directory trailing slash are retained separately from canonical destination. The sole canonical file coalescing rule is byte-identical regular members with distinct raw paths differing only by removing exact `.` components after the validated root; case variants, repeated raw paths, size/content mismatches, duplicate directories and file/directory conflicts remain forbidden. No raw archive path is passed to OS normalization for validation. Tar payload padding is required to be zero for every regular, directory and PAX member; tar symlinks, hard links, devices, FIFOs, unknown entry types, traversal, incomplete/ambiguous framing, and case/normalization collisions (including synthesized parent directories) are forbidden. Every archive header/member, including non-extracted PAX payloads and coalesced file aliases, is separately inventoried; member offsets are byte offsets in the uncompressed tar stream, and PAX binding points to the following member header.
